## Priority Issues

**[P1] Double-brass violates the system's own Named Rule**
- Why it matters: The active nav tab and the primary button are both rendered fully brass-filled simultaneously on every logged-in screen — DESIGN.md itself says "if two elements compete for brass, one of them is wrong." Both individually match their own component spec, meaning the system as documented guarantees this collision.
- Fix: Give the active tab a lower-emphasis treatment (Panel White + Brass Dial Deep text/border) and reserve solid brass fill for the one true primary action per screen; update DESIGN.md's Navigation section to match.
- Suggested command: $impeccable typeset

**[P1] Save confirmation is ephemeral with no persistent trace**
- Why it matters: Live-confirmed: "Synchronisé ✓" is fully gone by ~2.4s and the form is already blank. For an operator interrupted mid-task, the end-state is indistinguishable from "nothing was ever submitted."
- Fix: Leave a low-key persistent trace (a "dernière entrée" readout, or a longer/manually-dismissed confirmation) instead of a pure timeout.
- Suggested command: $impeccable clarify

**[P2] React duplicate-key race during offline→online reconnect**
- Why it matters: B reproduced this live twice: useSync's own online-triggered sync and EntriesList's own reload effect run independently, so there's a window where a just-synced entry exists both as a local draft and as a fetched server row, both keyed by the same id — a real React key-collision warning and a momentary duplicate/omitted card.
- Fix: Have EntriesList remove a draft from its local state as soon as it confirms the matching server row is present, instead of relying on two independent effects racing on the same online transition.
- Suggested command: $impeccable harden

**[P2] Inconsistent, partly un-branded error handling**
- Why it matters: LoginForm has no noValidate and shows raw Supabase strings verbatim (often English); friendlyErrorMessage() in EntriesList only catches network-pattern errors, letting everything else through raw.
- Fix: Add noValidate + the same custom validation pattern to LoginForm; replace the regex-based friendlyErrorMessage with a small central French error-code map.
- Suggested command: $impeccable clarify

**[P3] Numeric readouts lack digit grouping**
- Why it matters: "450000" renders as an unbroken string — correct typeface, harder to parse at a glance than "450 000."
- Fix: Locale-aware thousands separators on Readout-face values.
- Suggested command: $impeccable typeset

**[P3] Entry form fields aren't visually chunked**
- Why it matters: Five fields sit in one uniform stack with no distinction between the production count and the three financial figures.
- Fix: A thin divider or subgroup label to chunk the five fields into two conceptual groups.
- Suggested command: $impeccable layout
