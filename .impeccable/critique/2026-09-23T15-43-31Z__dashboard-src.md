## Priority Issues

**[P1] Primary buttons and the active nav item fail WCAG AA contrast — worse than the issue just fixed**
- Why it matters: `button.primary`, `.sidebar-item.active`, and the login Sign-in button all use white text on `--color-accent` (`#10b981`) = 2.54:1, well under 4.5:1. Same defect category as the just-fixed accent-deep issue, on every Save/Confirm button and the current-page indicator.
- Fix: Use `--color-accent-deep` (`#047857`, already verified ≥4.5:1 against white) as the background for these surfaces, or darken `--color-accent` for button/active-nav use.
- Suggested command: $impeccable harden

**[P1] Dashboard's KPI grid now shows a broken/unbalanced layout**
- Why it matters: `.totals-band` is hard-coded to 4 columns; with only 2 cards left, the landing page shows two empty 244px gaps on every desktop session.
- Fix: Switch to `grid-template-columns: repeat(auto-fit, minmax(220px, 1fr))` so the grid adapts to card count — also protects Expenses' 7-card band from the same problem.
- Suggested command: $impeccable polish

**[P2] A second orphaned CSS class — same failure mode as the original P0**
- Why it matters: `Clients.tsx` and `Fournisseurs.tsx` render `<span className="field-error">` for invalid payment amounts, and no `.field-error` rule exists anywhere. Same bug class as the button fix, on a real error path, silent to screen readers.
- Fix: Reuse the existing `.error` class (already carries `role="alert"`) or add a `.field-error` rule.
- Suggested command: $impeccable harden

**[P2] Keyboard focus is lost on every delete-row confirmation, app-wide**
- Why it matters: `DeleteRowButton` swaps the focused icon for Delete/Cancel buttons, but focus lands on `<body>` — verified via CDP. Affects Dashboard, Expenses, Sales, and Purchases (shared component); no `aria-live` either.
- Fix: `.focus()` the Delete or Cancel button on entering confirm mode; add `aria-live="polite"` to the swap region.
- Suggested command: $impeccable harden

**[P3] Mobile sidebar nav has no scroll affordance**
- Why it matters: Both assessments independently confirmed this — the nav row scrolls correctly but hard-clips at the viewport edge (e.g. "Sales" truncates to "Sa") with nothing signaling more items are reachable.
- Fix: Add a right-edge fade (`mask-image`) or a small chevron hint.
- Suggested command: $impeccable clarify
